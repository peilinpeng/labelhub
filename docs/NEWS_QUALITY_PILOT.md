# 新闻质量试用与人工复核

## 本轮范围与完成边界

2026-11-10，用户选择开放许可的公开新闻，并由用户完成最终人工判定。
已准备 24 条真实报道、逐条 AI 拟议标注与证据问题、独立空白人工任务及离线复核页；
AI 自动化走查已覆盖建任务、导入、标注、退回修改、审核和导出。
**尚无人工金标准，也没有人工试用耗时或真实模型质量结论。**
异盘备份、真实模型调用与评测、Agent 化和生产上线继续暂缓。

## 材料、许可与可追溯性

- 使用中文维基新闻的 24 篇报道，覆盖时政、财经、科技、社会、体育与文化，属于单一来源便利样本，
  不能代表全部新闻业务。报道按各自发布日期理解，不把旧报道当作当前事实。
- 依据[维基新闻版权说明](https://zh.wikinews.org/wiki/Wikinews:%E7%89%88%E6%9D%83%E4%BF%A1%E6%81%AF)，
  文本按 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 使用；不下载或复用图片。
  每条保留固定版本链接、贡献者历史链接、署名、许可、发布日期、原文列出的来源和转换说明。
- 同时保留 MediaWiki 原始响应快照与提取正文，分别计算真实 UTF-8 字节 SHA-256。
  提取去除导航、模板展示和图片；这不是完整网页档案。报道引用的第三方材料未被重新许可。
- 所有材料与操作记录仅位于本机 `.local/news-pilot-20261110/`，排除出 Git 和 Docker 构建。
  独立源文件保留在应用之外；同盘副本不构成异盘备份。
- 新闻含公开人物姓名，不能称为完全匿名材料；评测草稿不携带系统账号、任务/提交 ID 或认证信息，
  人工复核建议用代号。对外共享前仍需核对内容、署名与必要的数据最小化。

## 标注规范 v1

| 字段 | 规则 |
| --- | --- |
| 新闻类别 | 按主要事件选时政、财经、科技、社会或其他；体育、文艺暂归其他，不能多选 |
| 质量评分 | 1 严重不可用；2 有重大问题；3 需实质修改；4 基本可用但可改进；5 证据与表达明确充分 |
| 问题标签 | 标题党、事实不清、缺少来源、格式问题或无明显问题；“无明显问题”不得与其他问题并选 |
| 判定依据 | 每条必填，引用原文位置/片段及来源，区分内部矛盾、证据不足、待核查与已证伪 |
| 修改建议 | 给出可执行的修改；不要补写没有依据的事实；无需修改可明确说明 |

评分对象是新闻文本质量；审核结论判断的是**标注是否正确、充分**。低质量文章也可以拥有应当通过的标注。
原创报道不因缺少外链就自动判为无来源；来源数量也不等于可靠性。
未独立查证的事实只能标为待核查，AI 拟议标签不是事实裁定。
本轮模板复用新闻 Schema 与统一渲染器，关闭辅助节点和 AI 预审，始终要求判定依据；
标签互斥目前由规范和离线复核校验约束，产品多选控件仍允许冲突组合，人工审核须检查。

## 已执行的自动化走查

独立 Compose 项目和卷与业务环境分离，仅 Web 环回端口可访问；数据服务及模型处于内部网络。
新闻任务关闭 AI，模型接收记录为 0。建任务、文件导入、表单保存刷新、提交、审核确认和导出使用真实浏览器；
Schema 配置/发布及领取等辅助操作使用真实 API，未直接写业务表。

| 环节 | 次数 | 自动化累计秒数 |
| --- | ---: | ---: |
| 建任务及导入 | 1 | 0.51 |
| Schema 配置发布（API） | 1 | 0.05 |
| 标注、保存、刷新、提交 | 24 | 54.31 |
| 退回 | 6 | 2.50 |
| 修改重提 | 6 | 13.03 |
| 审核通过 | 24 | 7.63 |
| 导出下载 | 1 | 1.21 |

上述耗时来自脚本计时，只用于发现阻塞，不含人的阅读、核查或决策时间，不证明节省人工时间。
导出计时覆盖实际下载；最初对导出结构的断言失败后，单独按真实契约完成内容和护照复核，未重复计入该段。
24 条最终通过、6 条退回历史保留、30 次提交；导出 24 条唯一材料及其最终答案，全部护照的
`canonical-json-v1+SHA-256` 回算一致。匿名下载 401、Labeler 下载 403；浏览器无脚本错误。
另建独立人工任务，24 条均 AVAILABLE，没有复制自动化答案。

## 问题与处理

| 优先级 | 发现与处理 | 状态 |
| --- | --- | --- |
| P1 | 未配置或关闭 AI 预审时，提交停在 AI_REVIEWING，且无 worker 作业处理；现在在同一事务复用既有状态命令转 NEEDS_HUMAN_REVIEW | 已修复；缺失/禁用配置两项 API 回归及真实浏览器退回重提回归通过 |
| P2 | 人工判定易受预填 AI 标签影响 | 离线页默认收起 AI 建议，人工栏留空；必须主动确认，未裁定项不进入金标准 |
| P2 | 产品模板尚未自动拒绝“无明显问题”与其他标签并选 | 离线页拒绝冲突；产品试用按规范检查，记录人工误操作频率后决定是否增强通用校验 |
| 验收脚本 | 多选答案的等价顺序曾被误判；导出最初错误预期平铺 sourcePayload | 按真实选项顺序和 JSONL item.sourcePayload 契约修正；失败任务及证据保留，没有放宽产品规则 |

修复仅改变之后未启用预审的提交路由，不批量修改历史 AI_REVIEWING 记录；没有新增状态、API、共享字段或迁移。
既有 `AI_REVIEW_ENQUEUED` 的空 jobId 表示路由阶段，随后记录转人工原因；不表示投递了 Celery 作业。
完整 diff 自查为 AI 自查，不称人工 review。

## 用户如何继续

本机 `D:\AI_Projects\Labelhub\.local\news-pilot-20261110\开始这里.html` 是试用入口，包含：

1. `人工复核.html`：24 条原文、出处、可收起的 AI 拟议标签、空白人工栏和争议记录。
   建议先独立判断 N03、N08、N17、N18 校准规范，再逐条完成其余材料。只有亲自核对后才能保存为已确认。
2. 独立 LabelHub 人工任务：用测试角色走实际标注、退回、审核、导出；角色演练不代表独立多人审核。
   试用原系统工作台时使用入口中的手工耗时/障碍记录表；离线页计时仅反映该页复核。
3. 下载人工判定 JSON 与试用记录 JSON，保留在本机；浏览器本地暂存不是备份。
   无法判定的条目标为争议并说明所缺证据，不能为了凑齐样本强行通过。

对最终导出逐条抽查正文/来源、答案、返工后的最终版本和用途是否满足需求。
当前自动化验收不替代用户对标注口径、操作便利性、阅读负担及导出适用性的判断。

## 评测样本草稿与后续门槛

`review-draft.json` 保留 24 条 AI 提案、争议点和空白人工判定。预分开发集 18 条、保留集 6 条；

用户裁定后，先检查人工身份声明、理由、证据、冲突标签、争议状态及覆盖范围。

届时重点报告误放、误退、转人工、建议修改量、耗时、失败率与成本，保留分母与不确定性。
现阶段不运行真实模型、不宣称模型效果，不以 Agent 化作为完成条件。

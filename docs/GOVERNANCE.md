# 历史迁移、审批与任务权限

治理入口位于各角色工作台的「迁移与权限 / 迁移审批」。Owner 管理自己任务的授权；被授权的
Reviewer 或 Labeler 可以进入同一任务的治理工作台。ADMIN 可通过相同 API 管理所有任务。

## 使用流程

1. 在模板版本管理中确认源、目标两个已发布版本。现有破坏性发布闸门继续生效，迁移功能不授予绕过发布校验的能力。
2. Owner 在任务授权中给另一位有效用户授予 `migration.read` 和 `migration.approve`；可设置有效期。
3. 选择源版本、目标版本和历史提交；每批 1–500 条。填写明确的字段重命名、默认值、选项映射，按需选择归档删除字段。
4. 执行预演，检查操作、阻断原因、校验结果、样例前后对比与 SHA-256 摘要。输入超过 8 MiB 时缩小批次。
5. 提交独立审批；另一用户查看同一摘要并填写意见。自批、旧摘要、未通过预演的执行请求都会被服务端拒绝。
6. 执行已批准计划。后台 worker 生成独立迁移记录；页面刷新状态，可分页查看产物。原始答案、Schema 版本、审核和既有导出不变。
7. 源提交自预演后发生变化时，该条记录为 CONFLICT，整批为 PARTIAL；对冲突条目新建计划重新预演和审批。
   基础设施或权限问题导致 FAILED 时，修复后可重试，仍需有效的批准摘要与权限。

## 权限语义

- 任务动作包括任务管理、模板、数据集、导出、统计、标注、审核，以及分离的迁移读取/计划/审批/执行。
- 显式 DENY 优先于 ALLOW；过期和撤销即时失效。权限管理权只属于任务所有者/ADMIN，不能转授。
- ALLOW 作用于该任务，不改变用户的全局角色；例如 LABELER 不会因 task.manage 授权变成 OWNER。
- 既有角色和资源归属检查仍执行；认证每次读取用户 ACTIVE 状态和当前角色。
- 任务动作在幂等回放前检查，批量审核和列表/聚合入口也按任务过滤。
- ADMIN 为后端已有管理角色；此版本提供三个人工工作台的治理界面，管理员可使用受认证 API 进行跨任务管理。

## 存储与恢复

Alembic `f6a7b8c9d0e1` 新增 task_permission_grants、migration_jobs、migration_records。
升级 API 镜像与数据库后再启动 worker；生产禁止运行 demo seed。回滚应用前先停止新任务投递，完成或取消待处理计划并备份数据库；
生产不要执行会删除迁移记录的 Alembic downgrade。代码回滚保留新增表不会影响原有读写。

API 镜像通过 Node 26 构建并携带共享迁移引擎。开发环境在根目录执行 `npm ci && npm run build:migration-engine`，
确保 PATH 中有 Node 26（或设置 NODE_BINARY）。Python 仅负责授权、审批、快照与事务，使用既有 normalize_schema_payload 适配历史模板。

QUEUED 状态先提交到数据库，再投递到 Celery；scheduler 每分钟补投。worker 锁定任务和源提交，在单个批次事务中生成全部产物；
重复消息读取终态后退出。事务执行期间内部状态为 RUNNING，对外可能仍显示 QUEUED；崩溃回滚后可重新投递。
唯一约束 jobId+submissionId 防止重复结果；审计只保存 ID、状态、计数和摘要，不保存答案、prompt 或来源正文。
自定义验证器和 CUSTOM_TRANSFORM 未注册时阻断，不能跳过校验。

## 运行诊断

模板页打开「运行诊断」，可以查看依赖边、选择关注字段并试填。追踪显示初始化、字段变化、规则求值、AI patch 和递归保护事件；
只保存最近 200 条元数据，可暂停/清空，关闭或修改模板会清空。不会上传答案或追踪历史。

编译缓存依据完整 canonical Schema 内容失效，LRU 限制 20 份 / 8 MiB，并复制结果防止污染。诊断使用独立 WebWorker；
创建失败、崩溃、超时回退共享同步编译，取消和卸载忽略旧请求。普通 Formily 渲染同样复用缓存。

## Demo 与验证边界

Pages Demo 的治理记录存于浏览器本地，角色切换后可继续演示审批。Demo 执行同步模拟，复用相同迁移内核；
实际事务、队列、权限撤销和数据库恢复以真实 API/worker 测试为准。Demo 浏览器本地记录可被用户自行修改，不是可信审批凭证。

真实后端 E2E 验证版本选择 → 预演 → 自批拒绝 → 独立审批 → Celery 执行 → 产物与原始答卷不变；
单元/集成测试覆盖摘要篡改、冲突、未注册校验、过期授权、撤权回放、故障回滚、重复执行与 seed 外键顺序。
监控部署见 [运行监控](OBSERVABILITY.md)。

# 本机 Docker 存储恢复与验收

恢复日期：2026-11-03。适用环境：macOS APFS、Docker Desktop 4.56.0、Engine 29.1.3。
本次只修复本机运行环境并同步记录，产品代码仍为 PR #145 的基线。

## 故障与处理

宿主磁盘曾耗尽；Docker 虚拟机日志出现 ext4 写入错误，镜像内容读取和容器执行出现
`input/output error`。正常停止 Docker Desktop 并确认虚拟磁盘无打开句柄后，
使用 APFS 克隆保存 `Docker.raw` 和设置文件；重启后存储读取恢复。
随后发现 BuildKit 引用了不存在的快照，仅清理未使用的构建缓存，`docker system df` 恢复正常。
构建缓存首次清理报告回收 14.15 GB 逻辑空间，此数值不等于宿主实际释放空间。

完成验收后，删除本次隔离项目的容器、卷、网络与专用测试镜像，清理可重建的 npm/npx/pip
下载缓存，并使用 Docker 官方空间回收工具回收虚拟磁盘空闲块。
收尾检查宿主可用空间约 10.1 GiB；此数值是当时快照，后续构建仍需重新检查。
没有执行恢复出厂设置、容器/卷全局清理或虚拟磁盘缩容。

## 数据保护与证据边界

- 保留原有 12 个容器、7 个数据卷和原始镜像；容器 ID、配置、挂载、运行/停止状态逐项核对一致。
- 六个 LabelHub 服务健康；两个原有 PostgreSQL 服务均可接受连接；三个原本未运行的容器保持停止。
- 虚拟磁盘副本在 Docker 停止时创建，核对文件大小、独立 inode 和六处字节抽样；未宣称完整磁盘逐字节校验。
- MySQL 与两个 PostgreSQL 服务均保存全库逻辑备份；完整解压读取并计算摘要。
- 全部七个卷在短暂停写期间只读归档，验证压缩流与文件内容；逐个恢复到临时卷后用 `tar --compare`
  对比全部归档内容，全部通过。临时恢复卷随后删除。
- 停机磁盘副本与归档保存在仓库外的私有恢复目录，包含敏感数据，不提交 Git。
  APFS 克隆位于同一物理磁盘，只提供本地回退保护；不能代替异盘备份。
- 上述验证证明当前备份可读取、卷文件可恢复，不据此推断磁盘耗尽前的每一笔业务写入都成功。

## 下次构建前的容量检查

先检查承载 `Docker.raw` 的宿主卷空间，同时检查 Docker 存储是否可读：

```bash
df -h "$HOME/Library/Containers/com.docker.docker/Data/vms/0/data"
docker system df
```

本次隔离构建设置了宿主可用空间低于 10 GiB 则不启动的检查。10 GiB 是本次工作量的最低检查值，
不是任意构建都足够的保证；较大构建应额外预留空间。构建中持续观察空间，接近耗尽时停止本次构建，
优先清理可重建缓存和本次临时资源。APFS 快照/克隆可能使逻辑删除不能立即释放物理空间。

不要使用 `docker system prune --volumes` 清理未知项目；不要缩小 Docker 虚拟磁盘容量来缓解磁盘压力。
Docker 官方说明缩容会删除当前虚拟磁盘中的容器和镜像。
需要长期扩大容量时，先准备异盘备份，再通过 Docker Desktop 设置迁移存储位置。

## 恢复顺序

1. 保留当前故障现场、容器/卷清单和日志，停止新的构建及数据写入。
2. 优先将所需卷归档或数据库逻辑备份恢复到新建隔离卷/数据库，验证后再安排切换；不覆盖原卷。
3. 整机回退属于最后手段：完全停止 Docker Desktop，另存当前磁盘，再按官方恢复说明使用磁盘副本。
   本次修复前副本保留了当时的故障状态，不应作为“健康黄金镜像”直接覆盖正在运行的环境。
4. 恢复后核对原有清单、健康状态及关键业务链路，再执行隔离验收。

参考：[Docker Desktop 备份恢复](https://docs.docker.com/desktop/settings-and-maintenance/backup-and-restore/)、
[macOS 磁盘空间与回收说明](https://docs.docker.com/desktop/troubleshoot-and-support/faqs/macfaqs/)。
